## 阶段 0：接线与安全检查（**不通电**）

| # | 检查 | 判据 |
|---|---|---|
| 0.1 | BusLinker 的 **J8 跳线拨到 TTL 档**（1–3、2–4 短接） | 接错会完全无法通信，教程反复强调 |
| 0.2 | STM32 USART2（**PD5=TX / PD6=RX**）→ BusLinker **J1**（EX_TX/EX_RX/GND），**直连不交叉** | 若实测无响应，可临时对调 J1.1/J1.2 验证一次——这是唯一需要试错的地方 |
| 0.3 | **GND 必须接**（STM32 ↔ 舵机电源） | 半双工总线的硬要求；不共地会随机出错甚至打坏 IO |
| 0.4 | 舵机电源 **6.4–8.4 V**（7.5V 适配器或 2S 锂电） | ⚠️ **绝不能用 11.1 V** —— 那是给 HX 系列（11.1V 级）的，LX/HTS 会立刻过压损坏 |
| 0.5 | 功率路径**不要穿过 BusLinker 板**（大电流走机械臂电源侧） | 6 轴堵转理论上限 ~18A，随箱适配器只有 6A |
| 0.6 | 排线方向：黑→GND、红→V+、白/黄→SIG | 接反烧舵机 |
| 0.7 | ⚠️ **把 LeArm 原配控制板从舵机总线上摘掉** | 它不能再作为主控与 STM32 并存 |

**上力前先确认限位。** 6 个高扭矩舵机堵转电流可达数安培，会迅速过热；6A 适配器余量有限，**避免 6 轴同时堵转或同时急停**。

## 阶段 3：M1–M8 实测（按依赖顺序）

> 全部在树莓派上跑，`-p` 换成你的实际端口。
> 每个子命令都有 `--help`。

### M1 ⛔ 最关键 —— 电机模式下电位器是「截断」还是「回绕」

**它决定底座寻零走哪个分支**：截断型方向由读数贴哪根轨确定（不需要标志位），回绕型只能靠标志位猜。前者鲁棒得多。

```bash
# 1. 上力，然后切电机模式慢速转起来（转速 +200）
python3 _arm_probe.py -p /dev/ttyAMA0 torque 6 1
python3 _arm_probe.py -p /dev/ttyAMA0 mode 6 1 200

# 2. 连续观察一分钟，每 50ms 读一次，脚本会在结尾给判定
python3 _arm_probe.py -p /dev/ttyAMA0 pot 6 60

# 3. 停转（务必执行）
python3 _arm_probe.py -p /dev/ttyAMA0 mode 6 1 0
```

**看脚本结尾的判定行：**

| 输出 | 结论 | 动作 |
|---|---|---|
| `no wrap seen -> likely TRUNCATING` | 读数贴死某根轨、进窗才开始动 | ✅ `arm_cal.h` 保持 `ARM_POT_WRAPS 0` |
| `N wraps -> WRAPPING` | 读数连续变化、每 240° 跳一次 | ⚠️ 置 `1`，**并确认跳变间隔稳定等于 240°**；不稳定就不能用回绕方案 → 加 AS5600 |
| 读数**冻结不动** / 乱跳 | 电机模式读不到有效值 | ❌ 整条盲区方案不成立 → 必须加 AS5600（见设计文档 §7.10） |

**同时记录**（对第 3 种情况尤其重要）：回绕点是否**稳定在同一位置**，还是随机跳。

### M2 —— 电位器有效区 ↔ 机械角的对应

**先卸力**，否则伺服会跟你抢：

```bash
python3 _arm_probe.py -p /dev/ttyAMA0 torque 6 0
# 手动把底座从中位缓慢转到一端，另一边看读数
python3 _arm_probe.py -p /dev/ttyAMA0 pot 6 30
```

记录三件事：

| 项 | 含义 | 回填到 |
|---|---|---|
| `raw` 开始**线性变化**的角度区间 | 有效区 | `ARM_POT_LO` / `ARM_POT_HI` |
| `raw = 500` 时底座相对**车身正前方**的角度 | 中点机械角 | `ARM_POT_DEG_AT_RAW0`（当前假设 −120） |
| 贴边到开始变化的余量 | 贴边不可信区宽度 | 收窄或放宽 `POT_LO/POT_HI` |

> 后两项需要量角器或手机水平仪。**这是唯一需要手工几何测量的步骤。**

### M5 —— 速度 0 是否锁轴

```bash
python3 _arm_probe.py -p /dev/ttyAMA0 torque 6 1
python3 _arm_probe.py -p /dev/ttyAMA0 mode 6 1 0
# 手动轻推底座
```

- **推不动** → 锁轴，放心。
- **会溜** → 需要机械阻尼；并把 `ARM_VEL_KP` 调小（否则速度环会来回过冲）。

### M3 —— 速度标定（决定搜索容限）

```bash
python3 _arm_probe.py -p /dev/ttyAMA0 spin 6 300 5
```

输出末行是 `K = ... deg/s per speed unit`。`ARM_SPEED_1000_DPS = K × 1000`。

> **必须在满电和半电各测一次**，两个值都记下来。两者差多少，就是盲区积分误差的量级 ——
> 这是**这个方案最重要的一个不确定性来源**。
>
> **容限要求（已用 ±720° 线缆预算重算）**：有效上限 160 believed 度，够得着窗口要求
> `k_low ≥ 119.4/160 = 0.746` —— 也就是**标定高估真速不超过 34%** 即可。
> 安全侧完全不绑定（`(720−225)/160 = 3.09`）。所以容限是宽松的，但仍要测。

### M4 —— 加速段补偿角

```bash
python3 _arm_probe.py -p /dev/ttyAMA0 spin 6 300 1    # 含启动加速段
python3 _arm_probe.py -p /dev/ttyAMA0 spin 6 300 5    # 主要是匀速段
```

两次的**平均角速度**之差 × 加速时间 ≈ 该速度下丢掉的转角（预期 **1–5°**），回填 `ARM_ACCEL_COMP_DEG`。

### M7 —— 5 个位置关节的机械行程

出厂行程是 **pos 125…875**，但你的机构可能更窄。**用 `sweep` 慢慢走，听/看有没有撞限位**：

```bash
# 先卸力再上力，确认机构无卡滞
python3 _arm_probe.py -p /dev/ttyAMA0 sweep 1 --lo 125 --hi 875 --step 50 --dwell 800
```

逐个 ID1…ID5 各跑一遍（`--down` 反方向）。

**判据**：位置读数**持续跟着命令走**。若某处命令还在加大而读数**停住不动** → 已经撞上机械限位，记下那个位置，回填到该关节的实际上下限（Task 8 的下发处要按关节裁剪）。

> ⚠️ **不要在撞限位的位置停留** —— 堵转会迅速发热。

### M8 —— 帧间最小间隔

把 `HARDWARE/lx_servo.c` 的 `LX_GAP_US` 从 **500** 逐步降到 **400 / 300 / 200 / 100**，每档跑一次 6 轴联动（发一个 `0xAC` 帧）。
出现丢帧/不动作就**回退到上一档**，记录最小可用值。

## 阶段 5：端到端验收

| # | 动作 | 期望 |
|---|---|---|
| 5.1 | 上电 | 5 关节走到复位姿态；**底座自动慢速寻零**，找到有效区后停住 |
| 5.2 | 查 `0x56` 上报 | `status` bit1（`BASE_KNOWN`）置位；`pot_raw` 落在 `[POT_LO, POT_HI]` 内 |
| 5.3 | 发一个 `0xAC`：底座从 −225 转到 +225 | `base_state` 依次 `OK → BLIND → OK`；**回有效区时角度被拉回、误差清零** |
| 5.4 | 停在盲区里不动 30 秒 | `base_state` 保持 `BLIND`，不报漂移 |
| 5.5 | **把 `flags` bit0 常置**发 `0xAC` | 底座**只寻零一次**，不是反复寻（这是 Task 9 修的边沿触发，必须验） |
| 5.6 | 断开树莓派链路 | 200ms 内停住，`status` bit7（`ESTOP`）置位，**机械臂没有垮下来**（保持上力） |
| 5.7 | 重新接上链路 | **不自动续动**，要等新的 `0xAC` |
| 5.8 | 手动把底座掰到盲区，再断电上电 | 底座朝**正确方向**搜到有效区（方向来自读数贴哪根轨，不靠标志位） |

## 异常处理速查

| 现象 | 先查 |
|---|---|
| `id` 全部 `NO REPLY` | J8 跳线档位 / TX-RX 是否接反 / 共地 / 舵机电源 |
| 读到 ID 但发指令不动 | 是否上力（`torque <id> 1`）；位置模式下时间参数是否合理 |
| 某个关节撞限位还不肯停 | 立即 `torque <id> 0` 卸力；把该关节限位收窄后回填 |
| 底座寻零失败（`status` bit4） | M1 判定是否选错分支；`pot_lo/hi` 是否收得太窄；`ARM_HOME_READ_FAIL_MAX` 是否误触发 |
| 底座方向走反 | `ARM_POT_DEG_AT_RAW0` 的符号；对照 M2 的实测 |
| 6 轴起步不同步 | 不该发生（Task 8 已按 §7.9 排序并有断言）；若发生，查 `arm.c` 里 3a/3b/3c 的顺序 |
| 串口 `dropped` 疯涨 | ROS 驱动服务是否还在跑、抢串口 |

**任何时候不确定，先 `torque <id> 0` 卸力。** 保持上力时机械臂不会垮，但持续堵转/过热会伤舵机。

### Keil 编译

| 报错/警告 | 原因 | 处理 |
|---|---|---|
| `arm.c(521): warning: #185-D: dynamic initialization in unreachable code` | 已修（2026-09-26）。`if(!ARM_CAL_MEASURED)` 是**恒真**的编译期常量且 body 以 `break` 结尾，导致其后整段寻零代码不可达 | 已改成 `#if !ARM_CAL_MEASURED` / `#else` / `#endif`，两个分支都不会留下死代码 |
| `warning: #177-D: variable "home_read_fail" was declared but never referenced`（若出现） | 同一个根因的另一半：宏为 0 时寻零路径被编译掉，该变量只剩赋值 | 已把它的声明与重置也放进 `#if ARM_CAL_MEASURED` |

**自查命令**（两种宏值都验，零诊断才算过）：

```bash
python _ros_tooling/_syntax_both_ways.py
```

> 它会把 RVDS `portmacro.h` 里 5 处 Keil 专有 `__asm{...}` 在**临时副本**里中性化后跑 `gcc -fsyntax-only`
>（工程文件不动），然后**分别**以 `ARM_CAL_MEASURED=0` 和 `=1` 各跑一次 —— 因为 `#if` 选中的是**不同的代码**，
> 只验出货值会让另一个分支一直到 Task 10 置 1 的那一刻才第一次被编译。
>
> ⚠️ 旧脚本 `_syntax_arm_task9.py` 有两个坑：不做中性化会得到 **180 条级联假错**；把 gcc 的上下文行
>（`<path>: In function 'x':`，本身不带行列号）误当成诊断，报出**不存在的** `arm.c:383` 诊断。新脚本按
>"必须带 `file:line:col:`" 过滤。
