- 日期：2026-09-18
- 状态：设计已确认，待拆实现计划

## 1. 硬件前提

| 项 | 值 | 来源 |
|---|---|---|
| 灯带 | 2m × 60 灯/m，三灯一控（WS2811） | 用户 |
| 可寻址像素 | 120 灯珠 ÷ 3 = **40 像素** | 计算 |
| 安装方式 | **绕车身一整圈，首尾相接** | 用户确认 |
| 数据口 | **PA7** | 用户 |
| 供电 | **独立 DC-DC / 单独电源** | 用户确认 |
| 车身 | 600 × 400 mm，周长恰为 2000mm | 项目记忆 `l150pro-chassis-geometry` |

### 1.1 像素粒度

40 像素 / 2m = **每像素 50mm**（覆盖 3 颗灯珠）。人眼看不到"点"，只看到"色带"。**结论：不做点阵图案类灯效，只做色带/流动类灯效。**

### 1.2 引脚复用分析

`PA7` 当前完全空闲（GPIOA 上仅 PA8 被蜂鸣器占用）。可选复用：

| 复用 | 是否可用 | 结论 |
|---|---|---|
| **SPI1_MOSI** (AF5) | ✅ SPI1 全未使用 | **选它** |
| TIM3_CH2 (AF2) | ❌ TIM3 已配置为编码器模式 | 排除 |
| TIM8_CH1N (AF3) | ❌ TIM8 已用于舵机 CH1..4 | 排除 |
| TIM1_CH1N (AF1) | ❌ TIM1 已用于电机 PWM CH1..4 | 排除 |
| TIM14_CH1 (AF9) | ✅ TIM14 空闲 | 备选，无必要 |

**采用 SPI1 + DMA 方案**（最成熟、时序最稳）。

### 1.3 电气风险

- **逻辑电平**：MCU 输出 3.3V，WS2811（12V 型）的 DIN 高电平门槛可能高于 3.3V，存在间歇性鬼影/闪灯风险。
  **对策**：预留一颗 74AHCT1G125 或 74HCT245 做电平转换。不做也能跑，但要预期"偶发闪一下"。
- **亮度上限**：12V 60灯/m 满白约 **1.2A/m × 2m = 2.4A**。独立 DC-DC 可承受，但默认仍建议限幅（见 §6）。
- **物理红利**：WS2811 每通道电流固定（12V 下每通道串 3 颗灯珠），因此**纯红功耗仅满白的 1/3**。"极速红"恰好是最省电的状态，与安全语义一致。

### 1.4 时序参数

- SPI 时钟：84MHz ÷ 32 = **2.625 MHz**，bit 长 **0.381 µs**
- 编码：1 个 WS2811 bit → 3 个 SPI bit，`0 → 100`、`1 → 110`
  - `0` = 高 0.381µs / 低 0.762µs（规格 0.4 / 0.85µs）✅
  - `1` = 高 0.762µs / 低 0.381µs（规格 0.8 / 0.45µs）✅
- 一帧 = 40 × 24 × 3 = **2880 B** ≈ **8.8 ms** → 理论上限 ~100fps，实战跑 25fps

## 2. 坐标系统：索引映射

绕圈安装带来"方位"语义，但物理粘贴方向不可控。**用一层纯代码映射解决，不需要重焊或重新粘贴。**

```c
#define WS_DIR    1    /* +1 / -1：编号递增方向对应 顺 / 逆时针 */
#define WS_PHASE  0    /* 0..39：车头正前方那一格的编号 */

static u8 ws_map(u8 i) {                 /* 逻辑位置 → 物理像素 */
    /* +40 保证 WS_DIR = -1 时结果非负；% 40 收进有效范围 */
    return (u8)((WS_DIR * (s16)i + WS_PHASE + 40) % 40);
}
```

**规则**：

- **需要方位**的灯效（导航进度、未来的左右转向灯、环绕流光的流向）→ 走 `ws_map()`
- **不需要方位**的灯效（全圈同色、呼吸、爆闪）→ 直接用物理索引，无论怎么粘都是对的

### 2.1 各灯效的位置依赖

| 灯效 | 依赖物理索引 | 依赖方向 | 依赖零位 |
|---|---|---|---|
| 全圈同色（运动层） | ❌ | ❌ | ❌ |
| 待机呼吸 | ❌ | ❌ | ❌ |
| 环绕流光 | ❌ | ⚠️ 顺/逆会反 | ❌ |
| 转向流水 | ❌ | ⚠️ 顺/逆会反 | ❌ |
| 刹车 / 急停 / 低压 | ❌ | ❌ | ❌ |
| 导航到点（车头→车尾） | ✅ | ✅ | ✅ |
| 未来：左右半圈语义 | ✅ | ✅ | ✅ |

v0.2 灯效中**唯一真正吃绝对位置的是"导航到点"**。但映射机制现在就要建 —— 成本是一个函数加两个宏，以后加左右转向灯时不用返工。

### 2.2 标定模式

```c
#define WS_CALIB_MODE  0    /* 1 = 开机进入标定 */
```

标定态下 40 格只有 1 格亮白、其余全灭，串口每收到一个字符前进一格。把"车头正前方"那格的编号填入 `WS_PHASE`、"编号递增方向"填入 `WS_DIR` 即完成标定（约 10 秒）。

### 2.3 物理安装建议（软性）

灯带首尾相接的**接缝尽量放在车尾**，不要放在车头正中 —— 接缝处物理上是"39 → 0"的跳变点，做流水类灯效时会出现突兀的跳。若已粘好，调 `WS_PHASE` 让跳变点落在车尾亦可。

## 3. 分层架构与仲裁

```
┌─ L3 叠加层 ── 转向流水 / 刹车 / 急停 / 低压 / ROS断连   ← 可抢占
├─ L2 运动层 ── 全圈同色，色相 + 亮度 编码轮速
└─ L1 待机层 ── 静止时的呼吸 / 环绕流光 / 状态色
```

所有层只往**同一个帧缓冲** `u8 ws_frame[40*3]` 写字，最后统一刷出。

### 3.1 L1 ↔ L2 交叉淡入淡出

维护混合因子 `blend ∈ [0,1]`，L1 与 L2 之间做 **300ms 线性交叉过渡**，**禁止硬切**。硬切会让每次起步/停车出现视觉跳变。

### 3.2 静止/运动判定（必须带滞回）

编码器在停车瞬间有回弹抖动，无滞回会导致状态机在运动和静止之间疯狂翻转。

- 进入运动：`|v| > 0.03 m/s` 且**持续 100ms**
- 回到静止：`|v| < 0.015 m/s` 且**持续 500ms**

### 3.3 优先级

**急停 / 低压 > 刹车 > 转向 > 运动层 > 待机层**

L3 抢占分两类：

- **全带覆盖**：急停、低压 —— 完全接管画面
- **方向性叠加**：转向流水 —— 在运动层基色上叠加流动，不改变基色

事件退场做 **200ms 淡出**。

## 4. L2 运动层：全圈同色映射

### 4.1 设计动因

全圈同色意味着 40 个像素永远同色，"速度"只剩**色相**一个编码维度。而低速段色相全挤在青→绿这段冷色区，肉眼几乎无法分辨 —— 会产生"车已经动了但灯看起来没反应"的体验。

**对策：双维度编码 —— 色相为主，亮度为辅。**

### 4.2 色标（满量程暂定 0.75 m/s，按实车极速调整）

| 轮速 m/s | 色相 | 颜色 | 亮度系数 | 语义 |
|---|---|---|---|---|
| 0.02 ~ 0.10 | 160° 恒青 | `#00B4FF` | **0.35 → 0.75** | 起步蠕动 |
| 0.10 ~ 0.30 | 160° → 120° | 青 → 绿 | 0.75 → 0.90 | 慢速 |
| 0.30 ~ 0.50 | 120° → 60° | 绿 → 黄 | 0.90 → 1.00 | 巡航 |
| 0.50 ~ 0.65 | 60° → 30° | 黄 → 橙 | 1.00 | 快 |
| ≥ 0.65 | 30° → 0° | 橙 → **红** | 1.00 | 极速 |

**第一行是关键**：起步阶段色相锁死在青色，变化全部交给亮度。人眼对亮度比对色相敏感一个数量级，0.02 m/s 就能看见。

### 4.3 色相插值必须用 HSV

**禁止 RGB 线性插值** —— 从蓝插到红会经过发灰的紫红，观感浑浊。必须在 HSV 色相环上插值。

### 4.4 数据源与滤波

- 数据源：`|MOTOR_A/B/C/D.Encoder|` **实测值**（不是 `Target`），符合"实时转速"的要求
- 多轮取值策略：取各轮绝对值平均（全圈同色不需要区分左右）
- 滤波：**100ms 一阶低通 + 2% 滞回**，否则阈值附近灯会频闪

## 5. L1 待机层

绕圈安装在此有红利：可做**环绕流水**，直线安装做不了。

| # | 灯效 | 参数 | 用途 |
|---|---|---|---|
| A | **呼吸青** | 2.0s 周期，亮度 5% → 45% | 基础待机 |
| B | **环绕流光** | 3 像素光斑绕圈，周期 3s，色相青 | 等待指令，"活着"感 |
| C | **状态色呼吸** | 颜色 = 系统状态，呼吸 = 存活 | **推荐默认** |

### 5.1 状态色编码（方案 C）

| 颜色 | 含义 | 数据源 |
|---|---|---|
| 🟦 青色呼吸 | 正常待机 | 默认 |
| 🟨 黄色呼吸 | 等 ROS / 未收到 `cmd_vel` | ROS 连接标志 |
| 🟪 紫色慢闪 | ROS 断开 | ROS 连接标志 |
| 🟧 橙色呼吸 | 电池低压 | `adc.c` 电池电压 |

## 6. L3 叠加层

基色是全圈同色，因此**转向信息必须由叠加层提供**。

**采用"方向性流水"而非经典"左半圈黄闪"** —— 前者不破坏"全圈同色"的视觉基调，只给光带加流动方向。

| 事件 | 灯效 | 触发源 | 抢占方式 |
|---|---|---|---|
| **左转** | 保持当前速度色，叠加**逆时针**流动光斑，4Hz | `Move_Z` / 转向量超阈值 | 叠加 |
| **右转** | 同上，**顺时针** | 同上 | 叠加 |
| **刹车** | 色相强制拉 0° 红 + 亮度拉满 + 3 次快闪后回落 | 减速度超阈值（`Encoder` 变化率） | 全带 |
| **倒车** | 全带白色顺时针缓流 | 速度反向 | 全带 |
| **急停 / 避障** | **全带 8Hz 红色爆闪** | `Flag_Stop` / `Avoid_ON_Flag` | 全带 |
| **低电压** | 橙色慢呼吸，亮度压至 20% | 电池 ADC | 全带 |
| **导航到点** | 蓝色光点自车头流至车尾，跑完一圈 = 到达 | 里程 / 剩余距离 | 全带 |

## 7. 实现骨架

### 7.1 新增文件

- `HARDWARE/ws2811.c` / `HARDWARE/ws2811.h`（新建）

### 7.2 模块划分

| 模块 | 职责 | 可否宿主机测试 |
|---|---|---|
| `ws_spi_init()` | SPI1 + DMA2 初始化，PA7 复用配置 | ❌ 上板验证 |
| `ws_encode()` | 帧缓冲 → SPI 字节流（3 bit/bit 编码） | ✅ |
| `ws_hue2rgb()` | HSV → RGB，含亮度缩放 | ✅ |
| `ws_speed_map()` | 轮速 → 色相 + 亮度 | ✅ |
| `ws_state_machine()` | 静止/运动滞回判定 + `blend` 过渡 | ✅ |
| `ws_overlay_*()` | 各叠加层渲染 | ✅ |
| `ws_show()` | 触发 DMA 传输 | ❌ 上板验证 |
| `led_task()` | FreeRTOS 任务，周期调度 | 部分 |

### 7.3 关键宏

```c
#define WS2811_ENABLE     1     /* 总开关，0 = 全部关闭（保留代码） */
#define WS2811_PIXELS     40
#define WS2811_BRIGHT_MAX 80    /* 独立供电，上限可放宽 */
#define WS_DIR            1     /* 编号递增方向 */
#define WS_PHASE          0     /* 车头正前方像素编号 */
#define WS_CALIB_MODE     0     /* 标定模式 */
```

**遵循项目"只关入口不删代码"惯例**：全部灯效函数保留，仅通过 `WS2811_ENABLE` 宏与 `system.c` 中的调用点控制开关。

### 7.4 任务参数

- **固定 40ms 步长（25 fps），不随运动状态变化。**

  > 原方案是"静止时降到 10 fps 省电"，实现阶段发现两个问题：一是 `ws_state_step()` 的淡入步长和 100ms/500ms 滞回全按 40ms 标定，改成 100ms 会让 500ms 退出滞回实际变成约 1250ms；二是省电是假的——MCU 在 `vTaskDelay` 里同样休眠，灯带电流由 `WS_BRIGHT_MAX` 决定，与刷新率无关。故固定 40ms。
- 只在帧内容变化时才触发 DMA

沿用项目已有的**宿主机断言测试**模式（见 `_ros_tooling/_host_test.c`）：
