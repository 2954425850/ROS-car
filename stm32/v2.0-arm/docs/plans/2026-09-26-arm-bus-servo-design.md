### 1.1 由硬件前提直接推出的三条约束

1. **位置模式做不到 450°**：`0x14` 角度限位参数范围就是 0–1000（240°）。450° 只能靠电机模式。（《协议规范》§7.9）
2. **电机模式不掉电保存**：每次上电必须重发 `0x1D` 把 ID6 切到电机模式，否则它以位置模式抱死。（《协议规范》§7.9 限制①）
3. **电机模式不受角度限位保护**：`0x14` 只作用于位置模式，底座的 450° 边界只能靠固件软限位。（《协议规范》§7.9 限制③）

## 2. 目标与范围

### 2.1 目标

- STM32 通过 USART2 + BusLinker 直接驱动 6 轴机械臂（协议由 STM32 自己实现）
- ID1..ID5 位置模式；**ID6 电机模式 + ±225° 角度闭环**
- 底座在**电位器有效区内用绝对读数矫正误差**，在**盲区内纯开环积分**
- 上电自动初始化 + 底座自动寻零
- ROS 下发关节目标（`0xAC`）+ 固件回读全部 6 轴（`0x56`）
- 急停/失联安全兜底

### 2.2 非目标（本轮明确不做）

| 不做 | 理由 |
|---|---|
| 示教 / 动作组回放 | 用户确认不做；ROS 侧要演示可直接把动作组转成 `0xAC` 帧序列 |
| 逆解（末端坐标 → 关节角） | ROS 侧的事；固件只吃关节位置 |
| 关节角 ↔ 舵机 pos 的换算层 | 用户选定"全 raw"接口（§4.1）；换算在 ROS 侧 |
| 云台 PWM 通道（TIM12 CH5/6）的移除 | 硬件云台已被机械臂替换，但保留已验证路径不动（变死代码） |
| USART2 上的 APP/蓝牙遥控功能 | 该 UART 已专用于舵机总线 |

### 3.2 USART2 ISR 必须改的理由

现有 `USART2_IRQHandler()` 对**每个收到的字节**调用 `AT_Command_Capture()` 和旧的 APP 遥控解析（写 `Turn_Flag` / `Flag_Direction` / `Flag_Left` / `Flag_Right`）。

舵机的**应答包会从 USART2 收进来**，会被这套旧状态机吃掉字节、并写入无意义状态。所以 USART2 的接收路径必须切成舵机协议专用。

旧代码**保留在文件里**（`AT_Command_Capture()` 等函数不删），只是不再挂到 USART2 ISR 上。

## 4. 协议帧

所有帧沿用工程既有约定：小端、`len` = 帧总长、CRC-16/MODBUS（poly `0x8005` 反射 `0xA001`，init `0xFFFF`，refin/refout true，xorout 0）。工程内已有 `crc16_modbus()` 可直接用。

### 4.1 下行 `0xAC`（ROS → STM32），20 字节

```
idx sz  field      说明
 0  1   header 0xAC
 1  1   len    0x14
 2  2   p[1] int16  夹爪    0..1000
 4  2   p[2] int16  腕旋转  0..1000
 6  2   p[3] int16  腕俯仰  0..1000
 8  2   p[4] int16  小臂    0..1000
10  2   p[5] int16  大臂    0..1000
12  2   p[6] int16  底座   -1000..+1000   (0 = 中位, ±1000 ↔ ±225°)
14  2   t_ms uint16  0..30000  本次运动时间；0 = 用固件默认
16  1   flags uint8  bit0 = 请求底座重新寻零；其余保留
17  1   seq   uint8
18  2   crc   uint16 小端 CRC-16/MODBUS over bytes 0..17
```

### 4.2 量纲（已决策：全 raw）

| 字段 | 量纲 | 换算 |
|---|---|---|
| `p[1..5]` | 舵机原生位置 0–1000 | 换算在 **ROS 侧**（《协议规范》§5.8 的 `4.1667` 系数 + 方向符号 + 125..875 机械行程） |
| `p[6]` | int16 有符号，−1000..+1000 | `p[6] = base_deg / 225.0 × 1000`，**分辨率 0.225°/步**（比舵机原生 0.24° 更细） |

**理由**：与现有 `0xAB` 帧（发原始 PWM 微秒，换算在 ROS 侧）风格一致；5 个位置关节的原生控制量本来就是 0–1000；固件不做换算层 → 测试面最小，能先离线把舵机跑通再接 ROS。
底座 0.45° 的分辨率顾虑不成立：底座在盲区内的估算误差是 **5–13°** 量级（《协议规范》§7.12），远大于量化误差。

### 4.3 帧语义（已决策：单帧，不用模式标志位）

**一帧 = "6 个关节各自以 `t_ms` 匀速走到目标"。**

| ROS 用法 | 发帧节奏 | 效果 |
|---|---|---|
| 点到点（抓取/回零） | 偶尔发一次，`t_ms` 大（1000–2000） | 舵机自己匀速走完 |
| 视觉跟随（流式） | 20–50Hz 连续发，`t_ms` ≈ 帧周期 | 每个周期重新瞄目标 |

固件侧不做插值 —— 插值由舵机自己完成（`MOVE_TIME_WRITE` 的 time 参数）。所以**不需要"流式/点到点"两套模式**。

### 4.4 上行 `0x56`（STM32 → ROS），22 字节

```
idx sz  field      说明
 0  1   header 0x56
 1  1   len    0x16
 2  2   a[1..5] int16 ×5   5 个位置关节回读 0..1000
12  2   a[6]    int16      底座角度估计 -1000..+1000
14  2   pot_raw int16      底座电位器原始读数（标定/调试用）
16  1   status  uint8      bit0 臂在线 / bit1 底座角度已知 / bit2 底座在盲区
                           bit3 寻零中 / bit4 寻零或跟踪失败 / bit5 过温
                           bit6 欠压 / bit7 急停中
17  1   base_st uint8      底座状态枚举（§7.1）
18  1   seq     uint8
19  1   reserved 0
20  2   crc     uint16
```

**为什么新开一帧而不扩 `0xAA`**：与"下行不动 `0xAA`/`0xAB`"同一个理由 —— 28 字节的 `0xAA` 上行帧已在硬件上验证过，改它会让树莓派侧已验证的解析器一起失效。两种上行帧按 header 区分，与下行有 `0xAA`/`0xAB` 两种是对称的。另外回读率（20Hz）可以独立于底盘帧（50Hz）。

### 4.5 调试透传 `0xAD` / `0x57`（仅 bring-up，宏开关）

USART2 现在专用于舵机总线，PC 插不进去了（BusLinker 的 USB 档也不能与 TTL 档同时在线，见《协议规范》§2.7 纪律 1）。但 §11 的 M1–M5 实测**必须**在硬件上跑，所以加一条透传：

```
下行 0xAD:  [0xAD][len][timeout_ms u16][n u8][原始 0x55 帧字节 ×n][crc]
上行 0x57:  [0x57][len][seq u8][status u8][n_rx u16][收到的原始字节 ×n_rx][crc]
```

STM32 把 `0xAD` 里的原始字节**原样**发到 USART2，然后在 `timeout_ms` 内收集总线上的字节，装进 `0x57` 回传。

用 `#define ARM_DEBUG_PASSTHROUGH` 控制，**默认关闭**（出货固件不带）。有了它，树莓派上跑个 Python 脚本就能以 20ms 间隔轮询 `0x1C`，把 M1 测出来。

## 5. 舵机驱动层 `HARDWARE/lx_servo.c`

### 5.1 帧格式与校验

```
50 55 55 | ID | Length = 参数个数+3 | Cmd | Prm×N | Checksum
Checksum = ~(ID + Length + Cmd + Prm1 + ... + PrmN) & 0xFF
帧总长 = Length + 3
```

### 5.2 用到的指令

| 指令 | Cmd | Len | 说明 |
|---|---|---|---|
| `MOVE_TIME_WRITE` | 0x01 | 7 | 参数 = `posL, posH, tL, tH` **（位置在前、时间在后！）** |
| `MOVE_TIME_WAIT_WRITE` | 0x07 | 7 | 同上，只预置不执行 |
| `MOVE_START` | 0x0B | 3 | 广播触发（用 0xFE） |
| `MOVE_STOP` | 0x0C | 3 | 立即停 |
| `OR_MOTOR_MODE_WRITE` | 0x1D | 7 | 参数 = `mode, null, spdL, spdH` |
| `LOAD_OR_UNLOAD_WRITE` | 0x1F | 4 | 0=卸力 1=上力 |
| `POS_READ` | 0x1C | 3 | 应答 8 字节，**按有符号 short 解释** |
| `VIN_READ` | 0x1B | 3 | mV |
| `TEMP_READ` | 0x1A | 3 | ℃ |
| `ID_READ` | 0x0E | 3 | 广播 ID 时也应答，可扫未知 ID |

> ⚠️ **参数顺序唯一容易写错的地方**：`0x01`/`0x07` 是 **位置在前、时间在后**。《协议规范》§5.3 有原厂源码依据。写反了舵机会转到错误角度。

### 5.3 收发模型

- **TX**：阻塞轮询发送（沿用工程既有风格），帧间 `delay_us()` 忙等间隔（**不用 `vTaskDelay`**，tick 是 1ms 粒度给不出 0.5ms）。
- **RX**：USART2 RXNE 中断 + 字节状态机（与 USART1 的 `ros_rx_byte()` 同构），**ISR 内不调用任何 FreeRTOS API**。
- 半双工：总线上"写"和"读"不能同时；由 `arm_task` 的固定时隙串行调度保证。
- 写指令无应答；读指令**发完必须立即转接收**。

### 5.4 与《协议规范》§7.3 骨架的差异

骨架给的是 `HAL_UART_Transmit/Receive` 版。本工程用的是标准外设库（`USART_Init`/`USART_GetITStatus`）+ FreeRTOS，所以**照抄协议逻辑，不照抄 HAL 调用**。

## 6. 上电初始化（非阻塞状态机）

```
INIT_WAIT     延时 300ms（等舵机电源稳定）
INIT_TORQUE   ID1..6 逐个发 0x1F=1（上力）
INIT_PROBE    读 ID1 的 ID (0x0E)，200ms 超时 → 判断总线通不通
              ├ 有应答 → 继续
              └ 无应答 → 重试 3 次 → ARM_ABSENT（机械臂整体禁用，只上报）
INIT_CONFIG   ID6 切电机模式速度 0：0x1D mode=1 spd=0   ← 每次上电必做
INIT_POSE     ID1..5 用 WAIT_WRITE 预置出厂复位姿态 226/500/177/129/408
              + 广播 MOVE_START，t = 2000ms
INIT_HOME     底座寻零（§7.3）
READY         开始接受 0xAC
```

出厂复位姿态（《协议规范》§5.5.1）：ID1=226（夹爪）、ID2=500（腕旋转）、ID3=177（腕俯仰）、ID4=129（小臂）、ID5=408（大臂）、ID6=500（底座）。

健康检查（电压/温度）不放在初始化里，而是 READY 之后 **1Hz 轮转读**（6 秒一轮），避免上电时在总线上打一堆读帧。

## 7. 底座 ±225° 角度跟踪（本设计的核心）

### 7.1 状态机

```
BASE_UNKNOWN   上电，角度未知（未寻零）
BASE_HOMING    寻零中
BASE_OK        角度已知，且当前在电位器有效区（已重同步）
BASE_BLIND     角度已知，但当前在盲区（纯开环积分）
BASE_FAULT     寻零失败 → 底座停转保持上力，其余 5 轴仍可用
```

### 7.2 标定参数（存 Flash，实测后填）

```c
typedef struct {
    float pot_deg_at_raw0;   /* raw=0 对应的机械角 */
    float pot_deg_per_raw;   /* 每 raw 多少度，典型 0.24 */
    int16 pot_lo, pot_hi;    /* 有效区 raw 上下界（贴边不可信区） */
    int8  last_sign;         /* 最后在有效区时的角度符号。**仅回绕型用得上**
                              * —— 截断型直接看读数贴哪根轨，不靠它 */
    uint8 last_sign_valid;
    int16 speed_1000_dps;    /* 速度值 1000 对应的 °/s，实测标定 */
    float accel_comp_deg;    /* 每段加速补偿角（1~5°） */
    int16 soft_limit_deg;    /* 软限位，默认 225 */
    float search_bound_deg;  /* 首段搜索的位移上限（进度判据） */
    uint16 search_max_ms;    /* 单段搜索的时间上限 —— 与标定误差无关的安全网 */
} ARM_CAL;
```

`pot_deg(raw) = pot_deg_at_raw0 + pot_deg_per_raw × raw`，**仅在 `[pot_lo, pot_hi]` 内有效**。

### 7.3 寻零算法（50Hz 跑）

```
第一帧:  方向 = (raw > pot_hi) ? -1 : +1     /* 截断型：读哪根轨就决定往哪搜 */
                                             /* 回绕型：退回用 last_sign 推方向 */
         travel = 0 ; t = 0

循环:
    发 0x1D 速度 = 方向 × SEARCH_SPEED       /* 慢速，约 200 */
    raw = 读 0x1C ;  travel += SEARCH_SPEED_DPS × dt ;  t += dt

    if ( raw 落入 [pot_lo, pot_hi] )          /* 截断型：进窗即可信，不需要边界估计 */
        base_deg = pot_deg(raw)                /* 绝对角到手 */
        停车 → BASE_OK ; 更新 last_sign ; return 成功

    if ( travel >= SEARCH_BOUND 或 t >= SEARCH_MAX_MS )
        /* 截断型：不反向，搜不到就 FAULT（反向只会朝离窗口更远的方向走） */
        /* 回绕型：先反向再搜一次 */
        停车 → BASE_FAULT ; return 失败
```

**`SEARCH_MAX_MS` 是真正的安全网**：它与速度标定误差无关，所以即使电位器完全失效、距离记账不可信，位移仍有硬上界。

#### ⭐ 修正（2026-09-26，写实现计划时算出）：方向不该靠标志位猜

上面"方向 = 标志位的反方向"以及配套的安全证明，在写实现计划做数值推导时发现**不成立**，已修正：

**矛盾**：够得着窗口要求首段 ≥ **119.4°**（`soft_limit − pot_valid_half = 225 − 105.6`，标定偏低时还要更多），而"不超 ±360° 线缆预算"要求首段 ≤ **108°** —— 在 ±25% 速度误差下**无解**。更糟的是：若电位器彻底不响应，两腿搜索会把底座带到 `224 + 135 + 280 = 639°`，**直接扯断线**。

**漏掉的物理事实**：**截断型电位器的读数本身就指明了在哪一侧** —— 贴死 1000 说明角度为正（往负搜），贴死 0 说明角度为负（往正搜）。方向**根本不用猜**。

于是方案改为：

| | 截断型（`ARM_POT_WRAPS 0`） | 回绕型（`ARM_POT_WRAPS 1`） |
|---|---|---|
| 方向来源 | **电位器贴在哪个轨** | 标志位（唯一证据，**可能错**） |
| 反向腿 | **无**（`ARM_SEARCH_REVERSE 0`），搜不到就 `FAULT` | 有 |
| 安全性 | 方向必然朝向窗口，`|角度|` 单调减小，**原理上不可能跑飞** | 依赖标定精度，见下 |

**对用户担心的"断电时有人手动掰过"**：截断型下这**从原理上不可能导致错误** —— 手动掰过之后电位器贴在哪个轨，就是真实的那一侧，标志位陈旧与否无关。

**⚠️ 后续修正（2026-09-26，Task 6 执行时由数值推导推翻，原文的两条声明都不成立）**

初稿在这里声称加一条时间上限 `ARM_SEARCH_MAX_MS` 就构成"与标定误差**无关**的安全网"。**这是错的**：两个上限都是在 **believed 度**里计的，都要乘 `ARM_SPEED_1000_DPS`，所以它们**线性相关**，时间上限只是距离上限的另一种写法 —— 按 4600ms 算它给出 138 believed 度，而距离上限是 135，**距离上限绑定，时间上限完全冗余**。纯软件里**不存在**与标定误差无关的位移上界：真实的位移上界只能来自"舵机在该指令下的物理最大转速"（datasheet 常数）乘时间，而那个比值本身就决定了整个方案能不能成立。

**真正的约束（可行带推导）**：设 `k = 真实行程 / believed 行程`（标定误差），窗口半宽 `half = 105.6°`，软限位 `soft = 225°`，线缆预算 `B`：

| | 要求 | 化简 |
|---|---|---|
| 够得着窗口 | `cap ≥ (soft − half) / k_low` | `k_low ≥ (soft−half)/cap = 119.4/cap` |
| 不超线缆预算 | `soft + cap × k_high ≤ B` | `k_high ≤ (B−soft)/cap` |

**⭐ 线缆预算已确认为 `B = 720°`（用户澄清：从装配中位算 ±720°，不是 ±360°）。** 我此前按 ±360° 推导，得出"可行带只有 [−13%, +0%]"和"死电位器最坏到 393° 超预算"两个结论 —— **两个都是基于错误前提的，已作废**。

代入 `B = 720`、`cap = 160`：

| | 值 | 是否绑定 |
|---|---|---|
| 够得着窗口 | `k_low ≥ 119.4/160 = 0.746`（标定**高估真速不超过 34%** 即可） | ✅ **唯一绑定约束** |
| 不超预算 | `k_high ≤ (720−225)/160 = 3.09` | ❌ 完全不绑定 |

**死电位器最坏位移**：标定准确时 `225 + 160 = 385°`；`k_high = 1.25` 时 `225 + 200 = 425°` —— 都在 720° 内，**余量充足**。

| 我原先声称（按错误的 ±360° 前提） | 修正后（B = 720°） |
|---|---|
| ±25% 速度误差容限不可能 | **可容 ±25%，且高估侧余量到 30%+** |
| 时间上限是独立安全网 | **仍然不成立**（两个上限都经 `ARM_SPEED_1000_DPS`，线性相关，见下） |
| `ARM_SEARCH_BOUND_DEG = 135` | **改为 160**（吃掉 k_low = 0.746 的容限） |
| `ARM_SEARCH_MAX_MS = 3500` 足够 | **改为 5400**。3500ms 只给出 105 believed 度，距离上限需要 4500ms —— 时间上限先触发会让起点超过 ±210.6° 就无法回零，而 T6 用例里就有 ±224 的起点 |

**时间上限的性质（这一条修正仍然有效）**：`ARM_SEARCH_MAX_MS` **不是**与标定误差无关的安全网 —— 它与距离上限都要乘 `ARM_SPEED_1000_DPS`，两者**线性相关**，按 5400ms 算它给出 162 believed 度 > 距离上限 160，所以**距离上限绑定、时间上限冗余**。保留它只作为"估算器卡死"这类异常的后备。纯软件里不存在与标定误差无关的位移上界。

**新增防线**：`ARM_HOME_READ_FAIL_MAX = 5` —— 连续 5 拍（100ms）读不到电位器就报故障停转，而不是继续搜。这消除的是"电位器无应答"这一支，把最坏情形的持续时间从 5 秒压到 0.1 秒。

**回绕型（M1 若判定为它）**：靠标志位猜方向、且读数不给侧信息，容限要求比截断型严得多。**M1 若判定为回绕型，建议直接加 AS5600（§7.10）** —— 上电即知绝对角，整条盲区搜索连同它的安全论证一起消失。

> 实现细节见 `docs/plans/2026-09-26-arm-bus-servo-impl.md` Task 6，安全论证被 T6 的
> `test_homing_direction_from_rail` / `test_homing_survives_speed_error` / `test_homing_dead_pot`
> 三个用例钉成回归测试。

#### 窗口识别 —— M1 实测后定（关键未知量）

| 盲区表现 | 判据 | 能否直接给绝对角 |
|---|---|---|
| **截断型**（读数贴死 0 或 1000 不动） | **不需要额外判据**：`raw ∈ [pot_lo, pot_hi]` 成立即可信。窗外读数贴轨、进窗即变，`arm_pot_valid()` 自己就是充分条件 | ✅ 能。读数即绝对角，连线性度都不用信 |
| **回绕型**（读数连续，每 240° 跳一次） | 检测 `\|Δraw\| > 半量程` 的跳变帧 | ⚠️ 需结合"从哪侧进来"推理出是哪个回绕点 |

### 7.4 运行期跟踪（20Hz，且仅当估计值距边界 ≤20° 时才读）

```
每 20Hz:
    仅当 base_deg 估计距边界 ≤20° 时，才读一次 0x1C      ← 盲区深处不读
    if raw ∈ [pot_lo, pot_hi]:
        base_deg = pot_deg(raw)     /* 重同步，累积误差清零 —— 整个方案的关键 */
        last_sign = sign(base_deg)  /* 更新标志位（限频写 Flash，如每 5s 或每次重同步） */
        → BASE_OK
    else:
        base_deg += v_cmd_dps × dt  /* 盲区：纯开环积分 */
        → BASE_BLIND

    if |base_deg| > soft_limit:  发速度 0 + 上报
```

**"超出电位器范围后不读电位器"完全遵守** —— 盲区深处不发读指令、纯开环。唯一例外是**估计值距边界 20° 以内时恢复低频探测**，否则转回来时无法察觉。这既守住约束，又不会"回不来"。

**误差不累积**：每次回到有效区就用绝对读数把角度强制重同步、累积清零。总误差 = 单次盲区内最长连续转角的估算误差，而不是总行程的误差（《协议规范》§7.12）。

**软限位**：`base_deg` 估计超 ±225° 立刻发速度 0 并上报。盲区积分有 5–20% 误差，真实角可能略微超过 ±225°，但线缆有到 ±360° 的余量，安全。

### 7.5 底座速度环（点到点 / 流式共用同一个环）

```
err = base_target - base_deg
if |err| < 0.5°:  发速度 0 ; return

v_ff = err / (t_ms/1000)          /* 按时间的前馈 */
v    = v_ff + KP × err            /* + P 修正残差 */
v    = clamp(v, ±VMAX)
发 0x1D (mode=1, speed=v)
```

- **点到点**（`t_ms` 大，如 1500ms）：前馈主导，基本按给定时间走到。
- **流式跟随**（`t_ms` 小，如 40ms）：前馈被 `VMAX` 截断，退化为纯 P 环 —— 正是跟随想要的"误差越大转越快"。

### 7.6 与 5 个位置关节的同步

电机模式的 `0x1D` **立即生效，没有"预置+触发"机制**，所以"6 轴同时起跑"的正确顺序是：

```
① 依次发 ID1..5 的 0x07 预置（都不动）
② 发 ID6 的 0x1D 速度
③ 发广播 0x0B
```

②③ 之间只差一帧（115200 下约 0.9ms），对 450° 的底座旋转可忽略（《协议规范》§7.9 末）。

**急停时要单独给底座发速度 0** —— `MOVE_STOP` 对它无效。

## 8. 调度与时序预算

`arm_task` @ **50Hz**（20ms），优先级 **3**（低于 Balance=4，不低于 LED/WS2811=2）。**底座速度环跑满 50Hz，其余全部 20Hz**：

```
每 20ms 周期:
  ① 底座速度环 → 0x1D (10B)                      每周期        ← 必须快
  ② 5 轴广播 WAIT_WRITE×5 + MOVE_START (56B)     20Hz
  ③ 底座电位器读 0x1C (6B出+8B回)                 20Hz（且距边界≤20°才读）
  ④ 位置关节回读 0x1C ×2                          20Hz（轮转）
  ⑤ 健康检查 0x1B/0x1A                            1Hz
  ⑥ 上行 0x56                                     25Hz  ← 实测：`ARM_RATE_HZ/20` 整数除法得 2，故实际 25Hz
```

### 时序预算（115200，帧间间隔按 0.5ms 计）

| 项 | 频率 | 单次 | 均值占用 |
|---|---|---|---|
| 5 轴广播 | 20Hz | 7.9ms | 15.8% |
| 底座速度 | 50Hz | 1.4ms | 6.9% |
| 底座电位器读 | 20Hz | 1.7ms | 3.4% |
| 位置回读 ×2 | 20Hz | 3.4ms | 6.8% |
| 健康检查 | 1Hz | 1.7ms | 0.2% |
| **合计** | | | **≈33%** |

最坏 20ms 窗口内约 15ms（仍有余量）。

**如果实测偏紧，第一刀砍位置关节回读频率**（20Hz → 10Hz，或 2 个/周期 → 1 个/周期）。

> **实现注记（执行期更正）**：上表是**标称预算**，不是精确调度。实际实现里只有 ⑥ 用了分频器（且因整数除法落在 25Hz），②③④ 是**按条件每拍判定**的（5 轴广播看目标是否变化、电位器看是否距边界 ≤20°、回读固定 2 个/拍）。真实带宽占用需按 Task 10 的 `M8` 实测帧间间隔后重算。

### 实现约束

- **帧间间隔用 `delay_us()` 忙等**，不用 `vTaskDelay()`（tick 是 1ms 粒度，给不出 0.5ms）。忙等期间中断照常响应、Balance_task 优先级更高照常抢占，不影响 100Hz 底盘环。
- 《协议规范》§9.16 说"帧间 ≥0.5–1ms **或等上一帧 TC 完成**"。0.5ms 是取值，**列入待实测项 M8**。

## 9. 故障处理

| 条件 | 行为 | status 位 |
|---|---|---|
| USART2 无应答（ID1 探测失败 3 次） | 机械臂整体禁用，不发任何帧 | bit0=0 |
| 底座寻零失败（两方向都找不到边界） | **底座停转保持上力**，5 轴照常可用 | bit4 |
| 底座软限位触发 | 底座速度 0，等新目标 | — |
| 底座读电位器连续失败 >N 次 | 底座停转上报（防止积分跑飞） | bit4 |
| 舵机过温 >70℃ / 欠压 <6.4V | 上报（**不自动卸力**） | bit5 / bit6 |
| 急停 `ROS_FLAG_ESTOP` / 链路超时 200ms | 底座速度 0 + 5 轴 `MOVE_STOP`，**保持上力**；链路恢复后**不自动续动**，等新 `0xAC` | bit7 |

### 9.1 "接受新目标"的门槛

`ROS_FLAG_ENABLE=1 && !ESTOP && 链路正常`。

否则机械臂**保持上次目标不动**（不是卸力）—— 这样 ROS 只控底盘、不发 `0xAC` 时，机械臂不受影响。

### 9.2 为什么急停不卸力

6 轴机械臂一旦卸力会**因自重直接垮下来**，可能撞到车身或夹具。保持上力 + 就地停住既可恢复又安全（用户已确认）。

## 12. 风险与注意事项

### 12.1 红线

1. ⚠️ **舵机供电 6.4–8.4 V**，绝不能用 11.1 V。功率走机械臂原配电源，**不要穿过 BusLinker 板的铜箔**。
2. ⚠️ **必须共地**（STM32 ↔ 舵机电源）。半双工总线的硬要求。
3. ⚠️ **TTL 档时不要同时插 USB 上位机** —— 两路会被 J8 后级接到同一根 SERVO 线，互相抢线。
4. ⚠️ **改舵机 ID 时总线上只能接一个舵机**。
5. ⚠️ **电机模式不受角度限位保护**，底座的 ±225° 完全靠固件软限位 + 累计转角记账。

### 12.2 工程注意

6. 位置模式下 `MOVE_TIME_WRITE` 的 position 要**双向裁剪 0..1000**（原厂固件只裁了上限、没裁负值）。
7. 5 个位置关节的机械行程只有 **125..875**，别按全行程 0..1000 规划 —— 越界会撞机械限位堵转发热。
8. 夹爪（ID1）目标位置**限幅 ≤700**，防堵转（原厂做法）。
9. 读指令发完必须**立即转接收**；阻塞式接收前记得清残留标志。
10. 上电时序：先给舵机电源 → 再初始化 STM32 UART → 最后上力。
11. 写指令无应答 → STM32 无法靠 ACK 判断命令是否被接收。关键动作后读一次位置做闭环确认。
12. 电位器是**接触式**器件，连续旋转会加速磨损（0.24–0.3°/步）。这是底座方案的固有代价。

### 12.3 已知的精度局限

- 盲区内是**开环积分**，误差来源：速度标定误差 ε（±5~20%，随电池电压和负载变化）+ 加速段未计入（每段 1~5°）。
- 按 130° 盲区行程、ε=10% 估算，单次穿越盲区的误差约 **15°**；ε=20% 时约 **28°**。
- **误差不累积**：回有效区即重同步到 ±0.5°。所以底座"平时"（有效区内）指向精度很好，只有"跨盲区那一下"有偏差。
- 要 <5° 精度或"上电即知绝对朝向"，必须加 AS5600 外部编码器（《协议规范》§7.10）。**本轮不做**。
