## 1. 两个能力

| 能力 | 怎么用 | 产物 |
|---|---|---|
| **拍一张照片** | `k230ctl snap` | JPEG，路径打到 stdout；稳定路径 `/tmp/k230/latest.jpg` |

> ⚠️ 产物都在 `/tmp/k230/`，而 **`/tmp` 是开机清空的**（实测 `D /tmp 1777 root root 30d`）。
> 重启后 `latest.jpg` / `latest-result.json` 会消失，分别要等下一次 `snap` / 下一条结果才回来。
> **要跨重启保留就自己加 `-o` 指到别的目录。**
| **拿视觉结果** | 常驻服务 `k230-resultd` | `/tmp/k230/latest-result.json`（最近一条） |

```bash
IMG=$(/home/cy/k230-vision/pi/k230ctl snap)     # 一行路径
/home/cy/k230-vision/pi/k230ctl result --json   # 最近一条结果
```

## 2. 照片

- **1280x720 JPEG**，质量 90，典型 40~55 KB。
- **耗时实测 2.8~7.6 s（均值 ~6.3 s）**。慢的原因是板子的 RTSP 帧率低：
  **板子没有视频接收端时只有 ~8.4 fps**，攒够一个 GOP（25 帧）就要 3.6 s。
  云端接上视频后预计回到 1~2 s 量级 —— **但这还没实测过，别当已知结论。**
- **`snap` 会自动重试 3 次**：RTSP 拉流偶发起手就死（偶发率约 1/10），
  属于快速失败，重试很划算。
- **`suspect=true` 时画面可能不可靠**（没跨过 IDR）。`--json` 会给出 `frames`。
  默认 `--min-frames 30` 已经留了余量，正常情况不该出现 `suspect`。

## 3. 结构化结果

一行一条 JSON，换行分隔，来自 K230：

```json
{"ts": 1789690497000, "frame": 2080, "w": 1280, "h": 720,
 "objs": [{"cls": "orange", "score": 0.323, "box": [0.3188, 0.5844, 0.7219, 0.9938]}]}
```

- **`box` 是归一化坐标 0~1**，`[左, 上, 右, 下]`，直接乘显示尺寸即可，**不需要任何标定**
  （已验证 AI 帧与推流帧取景完全重合）。
- `cls` 是 **COCO 80 类**名。`objs` 可能是空数组。
- `w/h` 是**推流分辨率**（1280x720），不是推理分辨率（320x320）。
- `frame` 单调递增，**做帧对齐只能用 `frame`**。
- **`ts` 只有秒级精度**（K230 的 `time.time()` 返回整数秒），尾数恒为 `000`。只能当「大概是哪一秒」。

`resultd` 会额外加两个字段：`_received_at`（Pi 收到的时刻）、`_peer`（来源地址）。

### ⚠️ 3.1 上报频率取决于板子的推流有没有接收端

| 板子的 8555 视频接收端 | 结果上报频率 |
|---|---|
| 有（云端在收） | **~9.5 Hz** ✓ 与设计一致 |
| **没有（当前状态，云端未部署）** | **~0.9 Hz** |

同一原因也会把 RTSP 帧率从 ~30 fps 压到 ~8.4 fps。
**「结果怎么半天一条」先去看板子的视频有没有人收，不是 Pi 侧的问题。**

## 4. 远程改板子的 WiFi / 上报地址（8558，2026-11-18）

换网段 / 换 WiFi / 换 Pi 的 IP 时，**不用拔卡改 `config_local.py`**：

```bash
K=/home/cy/k230-vision/pi/k230ctl
$K config                                   # 看当前 SSID / 三个地址
$K config --result-host 10.64.35.7 --push-host 10.64.35.7
$K config --wifi-ssid MyWiFi --wifi-pass 'secret123'
$K config --clear                           # 删远程配置，重启后回到 config_local
```

可设：`wifi_ssid` / `wifi_pass` / `push_host` / `result_host` / `obstacle_host`
（`--obstacle-host ""` = 跟随 `result_host`）。值写进板子上的
`/sdcard/k230vision/config_remote.json`，**优先级高于 `config_local.py`**，
所以重启后仍然生效。

几个必须知道的边界：

- **ok 只代表"收到、校验通过"**。地址类会立刻重指；WiFi 是板子主循环里
  异步换的，可能要十几秒（换网期间没有画面/结果）。
- **WiFi 连不上会自动回滚到旧网络，并且不落盘**。只有真的连上新网，
  凭据才会被记住 —— 这是为了避免"写进磁盘的是一个连不上的网，板子重启后失联"。
  真实结果看 `k230ctl config` 输出里的 `last_apply`。
- **换网成功后板子的 IP 可能变**。`k230ctl` 默认用 resultd 记下的对端地址
  自动发现板子，别在脚本里写死 IP。
- **板子已经离线时这个入口没用** —— 任何网络入口都没有。那时还是拔卡改
  `config_local.py`。
- **没有鉴权**，局域网内谁都能发（和 8557 一样，信任边界是局域网）。

## 5. Pi 换 WiFi 时，把 K230 一起迁过去（`switch-net`）

**场景**：车上的 Pi 从一个 WiFi 换到另一个（IP 也会变），K230 必须**同时**换过去，
否则结果流/推流就断了。难点只有一个：**Pi 一旦离开旧网，就再也够不到还在旧网的板子**，
所以必须先安排、后切 Pi。

```bash
K=/home/cy/k230-vision/pi/k230ctl

# 推荐：Pi 在目标网有固定 IP / DHCP 保留
$K switch-net --ssid NewWiFi --new-host 10.64.35.7

# Pi 的新 IP 事先不知道：切完后在新网扫描 8558 自动找板子（同子网、无客户端隔离）
$K switch-net --ssid NewWiFi --password 'secret123'

# 扫描不可用（访客网隔离 / 不是 /24）但知道板子在新网的地址
$K switch-net --ssid NewWiFi --password 'secret123' --board-new-host 10.64.35.50

# Pi 由你自己换（桌面/GUI），命令只负责安排 K230 并在新网等它
$K switch-net --ssid NewWiFi --password '...' --no-pi-switch
```

命令做四步：

1. **旧网预检**：读板子当前的 WiFi/指向（8558），确认能通；
2. **先把安排发给 K230**：WiFi（+ 有 `--new-host` 时就连指向一起）——**此时 Pi 还在旧网**；
3. **切 Pi**（nmcli），拿新 IP；
4. **在新网让板子指向新 IP**：给了 `--new-host` 就不扫；否则扫同网段 8558 找板子，
   再用 `k230-resultd` 的收包计数验证结果流真的恢复了。

**默认后台执行**：换 WiFi 会把 SSH 一起踢掉，前台跑进程会跟着死。
日志 `/tmp/k230/switch-net-<时间>.log`，结果 `/tmp/k230/switch-net-status.json`；
本地终端想盯着过程加 `--foreground`。

失败时会发生什么（**先知道再按**）：

- **K230 连不上新 WiFi** → 板子自动回滚到旧网（坏凭据不落盘），但 Pi 已经过去了，
  两边分开。日志会给出 `nmcli connection up "<旧连接>"`，把 Pi 切回旧网就能找回板子。
- **Pi 连不上新 WiFi** → K230 可能已经过去了。先把 Pi 的 WiFi 连好再排查。
- 目标网有**客户端隔离**（访客网常见）→ 扫描永远找不到板子，别用自动发现模式。

两个硬件前提，很容易漏：

- **K230 的 WiFi 是 2.4GHz**。目标网如果是 5GHz-only，板子根本连不上，只会回滚。
- 最好不要用同名的 2.4G/5G 混合 SSID（band steering 可能把板子往 5G 推）。

**换完网后还有一件事**：在**换网段前**启动的 ROS 节点，DDS 发现会看着正常但
数据面收不到（2026-10-21 实测）。`switch-net` 不碰 ROS；按需重启
（通常是 `sudo systemctl restart ps2-teleop`，有时要带 `k230-resultd k230-framed
k230-bridge rosbridge` 一组）。详见项目记忆里的「Pi 换网段后的恢复」。

## 6. 边界说明

- **Pi 不做任何媒体转发。** 想「看界面」不需要 Pi 参与 ——
  任何设备直接拉 `rtsp://192.168.1.112:8554/k230` 即可（VLC/mpv 都行）。
- **`/dev/video0` 未实现**（2026-09-17 用户决定延期，需要装内核头 + DKMS 模块）。
- **没接进 voice-chatbot**（同样是用户决定；本轮只保证「照片取得出来」）。
- **结果流是「最新值」语义，不是可靠传输**：只保留最近一条，不排队、不存历史。
- 排错与全部实测记录（含失败与更正）：`/home/cy/k230-vision/NOTES.md`
  和 `pi/README.md`。
