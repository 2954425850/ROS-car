# K230 → 云端 对接说明

给实现云端收流 + 前端叠框的人。只写对接必需的事实，全部是 K230 侧实测结果。

## 1. 两条 TCP 连接，**K230 主动出站连你**

K230 是**客户端**，主动连云端 ⇒ 不需要打洞/转发/TURN，你只要在公网监听两个端口：

| 用途 | 端口（现指向树莓派，云端就绪后改） | 载荷 |
|---|---|---|
| 视频 | 8555 | **裸 H.264 Annex-B 字节流**，无容器、无协议封装、无音频 |
| 结构化结果 | 8556 | **换行分隔 JSON**（一行一条，`\n` 结尾） |

改地址的地方：K230 的 `/sdcard/k230vision/config.py` → `PUSH_HOST/PUSH_PORT`、`RESULT_HOST/RESULT_PORT`。
另预留 `CLOUD_RESULT_HOST/CLOUD_RESULT_PORT`，留空 = 禁用结果上云（目前就是空的，只发树莓派）。

## 2. 视频流的确切性质

- **H.264 Annex-B**（起始码 `00 00 00 01`），**720p30**，**~2 Mbps**（实测均值 1.92 Mbps）
- **GOP = 25 帧**（0.83 s）
- **每个 IDR 前都重复发 SPS/PPS**；流开头就是 `SPS, PPS, IDR`
- 无音频。`ffmpeg -i pipe: -c copy` 可直接吃（**不转码**）
- 典型管道：`TCP 收流 → ffmpeg -c copy → mediamtx → WebRTC(WHEP)/HLS → 浏览器`

### ⚠️ 2.1 流会被频繁打断 —— 硬要求，不是边角情况

30 分钟长稳实测：**~57 次真实断连**（平均 33 秒一次），每次 **≤1.6 秒**自愈，
累计损失 1.8% 时间，吞吐不受影响。收流器必须：

1. **不要把一次 EOF/断开当成"流结束"** —— 要循环 accept + **重启 ffmpeg 管道**。
2. **不要把"收到第一个字节"当成"可以开始解码"** —— **重连后的流是从 P 帧接上的**
   （实测重连后起手 10+ 个 NAL 全是 P 帧，第一个 SPS 可能在 ~0.46 s 之后）。
   **必须丢弃直到首个 SPS/IDR 再开始解码/统计**，否则前半段花屏或解码报错。
3. 关键帧恢复上界 = GOP = **0.83 s**（K230 **无法主动请求 IDR**，该平台没有此接口）。

## 3. 结构化结果 JSON

一行一条，`\n` 分隔：

```json
{"ts": 1789646346, "frame": 200, "w": 1280, "h": 720, "objs": [{"cls": "apple", "score": 0.503, "box": [0.3625, 0.1219, 0.7812, 0.8344]}]}
```

- **`box` 是归一化坐标 0~1**：`[左, 上, 右, 下]`。直接乘你的显示尺寸即可。
- `cls` 是 **COCO 80 类**名（`person`…`apple`）。`objs` 可能是空数组。
- `w/h` 是**推流分辨率**（1280×720），不是推理分辨率。
- **频率 ~8.5~10 Hz**（短跑 10.0、30 分钟长稳 8.5），量级几 KB/s。

### ⚠️ 3.1 `ts` 只有秒级精度，帧对齐只能用 `frame`

K230 上 `time.time()` 返回**整数秒**（实测），`ts` 尾数恒为 `000`。
→ **请用 `frame` 做对齐键**；`ts` 只能当「大概是哪一秒」。

### ⚠️ 3.2 结果与视频是两条独立连接

顺序不保证，允许几十 ms 错位。`frame` 单调递增，可用于对齐。

## 4. 叠框：归一化坐标可直接用，**不需要任何标定**

同一次管线里把 AI 帧与推流帧各 dump 一帧做比对：

- AI 帧与推流帧**取景完全重合**：零位移相关 **0.9990**，最佳位移恰好 **(0,0)**（负对照 0.3651）
- 同一个苹果的归一化框，两边差 **≤0.0016**（≤0.16% 画面）

→ **前端把 `box` 乘以自己的显示尺寸即可**，不需要偏移/缩放标定。
（「原画 / 带框」切换 = 前端一个开关，零带宽代价。）

---

## 5. 容量

- 视频：单路 **2 Mbps** 上行（K230 侧）。**家宽上行能否稳定扛住未验证**（设计文档 V1）。
- 结果：单路 ~**10 条/秒**，每条 ~150 B。
- 云端 `-c copy` 无转码，负载很轻。
