# 腕上 ToF 深度链路 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 K230 在视觉结果流里给每个目标框附上 A010 ToF 实测深度，Pi 用它算出目标三维点，并把单目多视角测高整条删掉。

**Architecture:** K230 是唯一接触传感器的地方 —— 主循环里用非阻塞 `TofReader.pump()` 收帧，用一个纯逻辑模块把「归一化框 → ToF 区域 → 最小有效深度 → 毫米」算出来，挂在 `objs[i].depth_mm` 上随 8556 流发出。Pi 只多解析一个字段，把「射线 ∩ 假设平面」换成「射线 × 实测光轴深度」。深度图不上网。

**Tech Stack:** K230 CanMV MicroPython（板侧）、Python 3.12 + ROS 2 Jazzy（Pi 侧）、pytest、pyserial（PC 侧跑板测试）。

**设计文档:** `pi/docs/superpowers/plans/2026-10-10-tof-depth-design.md`（含全部实测证据，先读它）

## Global Constraints

- 深度字段名固定 **`depth_mm`**，**毫米整数**；无效时 **`null`**（不是 0、不是 -1）。**Pi 见 `null` 一律拒绝，绝不回落成常数。**
- `depth_mm` 的含义固定为 **目标表面在相机光轴方向的深度 Z**（不是欧氏距离）。
- 8556 结果流**只加字段**；既有字段、节拍、`encode()` 签名不变。
- **不把深度图或任何图像发到 Pi。**
- ToF 读帧**绝不能在主循环里阻塞**（板子有"一个 sleep 把整条链路拖到 1 Hz"的前科）。
- `AT+BAUD=` **收索引不收波特率数值**；`3`=230400、`5`=921600。
- **`pi/k230-board/` 顶层的 `*.py` 就是板子 `/sdcard/k230vision/` 里的文件**；`pc/` 子目录只跑在 PC 上。
- 新增测试**必须先做变异自检**（改坏实现要能变红），否则不算证据。
- 任何改动都**只走 git**：本地写 → push → Pi `git pull` → 重启；不在 Pi 上直接改。
- 涉及真机的步骤**不要自动跑**，列出来交给操作者。

>    而本工具一次只送一个文件。`--module tof_locate.py` 会把模块源码拼在测试前面 +
>    一个 `sys.modules` 垫片，**模块与测试两个文件都逐字不改**。
>    ⚠️ 垫片不能用 `sys.modules['__main__']` —— MicroPython 的 raw REPL 里**没有**它
>    （实测 `KeyError: '__main__'`），要用「造空对象 + 复制 globals」那版。

```python
"""把本地脚本送到 K230 上跑（PC 侧）。

为什么不用 mpremote：`/sdcard/main.py` 上电自启会挡死 raw REPL，而 **mpremote 打开串口会
翻转 DTR 复位板子** ⇒ 它一开就撞上正在启动的 app.py，永远进不去（2026-10-10 实测）。
这里在一个连接里做完全部动作：Ctrl-C 猛打 → Ctrl-A → 送码 → Ctrl-D → 收输出 →
收尾 Ctrl-B + Ctrl-D 软复位把 app 拉回来。

用法：python pc/board_exec.py ../../k230-board/t_tof_locate.py
"""
import argparse, re, sys, time
import serial


def run(port, code_path, boot_wait_s=40.0, exec_timeout_s=150.0, baud=115200):
    code = open(code_path, "rb").read()
    s = serial.Serial(port, baud, timeout=0.2)
    s.reset_input_buffer()

    buf, end = b"", time.time() + boot_wait_s
    while time.time() < end:
        s.write(b"\x03\x03")
        time.sleep(0.25)
        d = s.read(8192)
        if d:
            buf += d
            if b">>>" in buf[-800:] or b"raw REPL" in buf[-800:]:
                break
    else:
        s.close()
        print("连板子失败：Ctrl-C 打不进 raw REPL", file=sys.stderr)
        return 1

    s.write(b"\x01")          # 确保在 raw REPL
    time.sleep(0.4)
    s.read(4096)
    # ★ 分块慢送（2026-10-12 真机实测补的，初稿是 `s.write(code)` 一坨 —— **必失败**）。
    #   这条 USB-CDC **不看波特率**：`s.write(code)` 是 USB 全速下发，板子 REPL 的接收
    #   环形缓冲吃不下 5KB 就**丢掉最前面那段**（实测 5605 字节的 t_tof.py 一坨送 ⇒
    #   只有文件尾部被执行，报 `File "<stdin>", line 3 ... NameError:
    #   name 'frame_with' isn't defined`；`frame_with` 在文件第 113 行，报错却在
    #   编译单元第 3 行 ⇒ 前面整段没了）。分块 + 小间隔就全到。
    #   ⚠️ 小心别被"我以前一坨送成过"误导：本会话早期的手写脚本只有 2.5~2.7KB，够小才侥幸过。
    for i in range(0, len(code), 128):
        s.write(code[i:i + 128])
        time.sleep(0.02)
    time.sleep(0.3)
    s.write(b"\x04")

    out, end = b"", time.time() + exec_timeout_s
    while time.time() < end:
        d = s.read(4096)
        if d:
            out += d
            if b"<<EOT>>" not in out and out.count(b"\x04") >= 2:
                break
        else:
            time.sleep(0.02)

    try:                      # 收尾：把 app.py 拉回来
        s.write(b"\x02"); time.sleep(0.3); s.write(b"\x04")
    except Exception:
        pass
    time.sleep(0.5)
    s.close()

    text = out.decode("utf-8", "replace").replace("\x04", "\n")
    print(text)
    bad = bool(re.search(r"\bFAIL\b|Traceback|EXC", text))
    return 1 if bad else 0


if __name__ == "__main__":
    ap = argparse.ArgumentParser()
    ap.add_argument("script")
    ap.add_argument("--port", default="COM11")
    a = ap.parse_args()
    sys.exit(run(a.port, a.script))
```

### Task 1: 纯逻辑模块 `tof_locate.py` —— 框 → 最小有效深度 → 毫米

**这是整个 P1 最要紧的一块。** 实测教训：取中心区**最小**比取中位数准 20 mm
（420.6 vs 440.6，尺量真值 41~42 cm），但**裸取全局最小**会被爪尖/臂身的近场假回波
（实测 12 计数 = 48 mm、30 计数 = 120 mm）拉到场强。所以是 **「取最小」+「150 mm 量程下限」**。

> ★ **2026-10-12 修正**：初稿在这里写的是「按深度一维聚类，取最靠前的一簇」。
> **那个算法数学上就分不开** —— 40 cm 处瓶盖顶面与桌面只差 **3 计数**，而同一个面
> 因倾斜就有 ~8 计数散度。任何 jump 要么合掉盖子、要么把面切碎。
> 实测证据：初稿自带的用例期望 420 mm、**实得 440 mm**。已换成现在这个算法。

**Files:**
- Create: `pi/k230-board/tof_locate.py`
- Test: `pi/k230-board/t_tof_locate.py`

**Interfaces:**
- Produces:
  - `box_to_region(box_norm, rows, cols, map_cfg, pad=0.06) -> (r0, r1, c0, c1)`；越界裁剪；完全出界返回 `None`。
  - `region_depth(frame, region, unit_mm, min_mm=150, val_max=254) -> int | None`；`frame` 是 `a010_frame.feed` 出来的 dict。
  - `locate_depth(frame, box_norm, unit_mm, map_cfg, pad=0.06, min_mm=150, val_max=254) -> int | None` —— 上面两个的组合，**这就是 app.py 要调的那一个**。
- 模块级常量 `MIN_MM = 150`、`VAL_MAX = 254`（供 Task 3 的 `config.py` 引用）。
- `map_cfg` 是 dict：`{"ax": 1.0, "bx": 0.0, "ay": 1.0, "by": 0.0}`，含义
  `tof_x = ax * stream_x + bx`、`tof_y = ay * stream_y + by`（都是归一化 0~1）。
  默认恒等 —— 假设 ToF 与相机近似共轴同视场；标定就是量这四个数（Task 4）。

```python
# /sdcard/k230vision/tof_locate.py —— 框 → ToF 区域 → 最小有效深度（**纯逻辑**）
#
# 和 a010_frame.py 一个路子：把不碰硬件的东西拎出来，好在板上零风险测红。
#
# ## 为什么取「最小」而不是中位数/中心像素
#
# 2026-10-10 实测（41~42cm，UNIT=4，25 帧）：
#   * 中心区**最小** 420.6mm / 1σ 2.9mm；**中位数** 440.6mm（差 20mm）；
#     **中心单像素** 448.3mm（差 28mm）。尺量真值 41~42cm ⇒ **最小最接近真值**。
#
# ## 为什么要 150mm 量程下限
#
# ToF 视野里能看到爪子/臂身，产生**近场假回波**（实测 12 计数 = 48mm、
# 30 计数 = 120mm）—— 裸取最小会被它们拉到场强。模块**额定下限就是 15cm**，
# 比它还近的回波按定义不可信 ⇒ 直接滤掉。
#
# ## 为什么不做一维聚类（做过，2026-10-12 废弃）
#
# 40cm 处 100x100、UNIT=4 时，瓶盖顶面与桌面只差 **3 计数**，而**同一个面**
# 因倾斜/纵深就有 ~8 计数散度 ⇒ 任何 jump 不是把盖子与桌面合掉、就是把面切碎。
# 实测：聚类版对「目标 + 桌面」的用例给出 440mm（中位数口径），错 20mm。

VAL_MAX = 254          # ★ 255 = 无效/超量程（模块的约定），必须滤掉，别拿来当「距离」
MIN_MM = 150           # ★ 模块额定量程下限 15cm；比这更近的回波是伪影（爪尖/臂身/多路径）


def _region_bounds(box_norm, rows, cols, map_cfg, pad):
    l, t, r, b = box_norm
    if r <= l or b <= t:
        return None
    ax, bx = map_cfg.get("ax", 1.0), map_cfg.get("bx", 0.0)
    ay, by = map_cfg.get("ay", 1.0), map_cfg.get("by", 0.0)
    x0, x1 = ax * l + bx, ax * r + bx
    y0, y1 = ay * t + by, ay * b + by
    if x0 > x1:
        x0, x1 = x1, x0
    if y0 > y1:
        y0, y1 = y1, y0
    c0 = int((x0 - pad) * cols)
    c1 = int((x1 + pad) * cols + 0.999)
    r0 = int((y0 - pad) * rows)
    r1 = int((y1 + pad) * rows + 0.999)
    if c1 <= 0 or r1 <= 0 or c0 >= cols or r0 >= rows:
        return None                      # 完全出界
    r0 = max(0, min(rows, r0))
    r1 = max(0, min(rows, r1))
    c0 = max(0, min(cols, c0))
    c1 = max(0, min(cols, c1))
    if r1 <= r0 or c1 <= c0:
        return None
    return (r0, r1, c0, c1)


def box_to_region(box_norm, rows, cols, map_cfg=None, pad=0.06):
    """归一化框（推流坐标）→ ToF 像素区域 (r0, r1, c0, c1)；完全出界返回 None。"""
    return _region_bounds(box_norm, rows, cols, map_cfg or {}, pad)


def region_depth(frame, region, unit_mm, min_mm=MIN_MM, val_max=VAL_MAX):
    """区域内**最小**有效计数 → 毫米；没有合格值返回 None。"""
    rows, cols, pl = frame["rows"], frame["cols"], frame["payload"]
    r0, r1, c0, c1 = region
    if rows == 0 or cols == 0 or len(pl) < rows * cols:
        return None
    lo = max(1, int(min_mm / unit_mm + 0.999))    # 向上取整：只接受 ≥ min_mm 的值
    best = None
    for r in range(r0, r1):
        base = r * cols
        for c in range(c0, c1):
            v = pl[base + c]
            if lo <= v <= val_max and (best is None or v < best):
                best = v
    return None if best is None else best * unit_mm


def locate_depth(frame, box_norm, unit_mm, map_cfg=None, pad=0.06,
                 min_mm=MIN_MM, val_max=VAL_MAX):
    """app.py 要调的那一个：框 → 深度（毫米整数）或 None。"""
    if frame is None:
        return None
    region = box_to_region(box_norm, frame["rows"], frame["cols"], map_cfg, pad)
    if region is None:
        return None
    return region_depth(frame, region, unit_mm, min_mm, val_max)
```

```python
_PROBE_ORDER = (115200, 230400, 921600, 460800, 3000000)


def open_tof(fast=True, unit=TOF_UNIT):
    """开一个 A010 会话，可选提速到 921600。返回 (dev | None, baud | None)。

    * **先探测**模块挂在哪个波特率上 —— 掉电默认是 115200，但别假设
      （改过波特率又没断电时它还在别处；模块的设置掉电不保存，见文件头）。
    * 提速顺序：停流 → AT+BAUD=5 → **关掉再用新波特率重开** → 开流。
    """
    dev = None
    for b in _PROBE_ORDER:
        d = A010(baud=b)
        if d.ping():
            dev = d
            break
        d.close()
    if dev is None:
        return None, None
    dev.init(unit=unit)
    if not fast:
        return dev, dev.baud
    dev.stop_stream()
    dev.set_baud_index(FAST_BAUD_INDEX)
    dev.close()
    time.sleep_ms(600)
    dev = A010(baud=BAUD_INDEX_TO_RATE[FAST_BAUD_INDEX])
    if not dev.ping():
        dev.close()
        return None, None
    dev.stop_stream()
    dev.cmd("AT+UNIT=%d" % unit)
    dev.cmd("AT+BINN=1")
    dev.cmd("AT+FPS=19")
    dev.start_stream()
    return dev, dev.baud


class TofReader:
    """非阻塞取帧：每拍最多读 max_reads 块，没数据就立刻返回。

    **绝不在主循环里长等** —— app.py 的主循环同时喂着推流/RTSP/推理，
    板子上已经有"主循环里一个 sleep 把整条链路拖到 1Hz"的前科。
    """

    def __init__(self, dev, chunk=READ_CHUNK):
        self.dev = dev
        self.chunk = chunk
        self.buf = b""
        self.latest_frame = None
        self.frames = 0

    def pump(self, max_reads=4):
        got = 0
        for _ in range(max_reads):
            d = self.dev.uart.read(self.chunk)
            if not d:
                break
            self.buf += d
            fr, self.buf = a010_frame.feed(self.buf)
            if fr is not None:
                self.latest_frame = fr
                self.frames += 1
                got += 1
        return got
```

```python
def attach_depths(objs, frame, unit_mm, map_cfg=None, classes=None,
                  max_boxes=3, pad=0.06, min_mm=MIN_MM):
    """就地给 objs 里的目标框挂 `depth_mm`（毫米整数，或 None）。

    只处理 `classes` 里的类（None = 全部），且**最多 max_boxes 个**（按框面积从大到小）——
    MicroPython 下逐像素的 Python 循环很慢，框一多会让 10Hz 的推理节拍掉帧。
    """
    picks = [o for o in objs if classes is None or o.get("cls") in classes]
```

```python
# -*- coding: utf-8 -*-
"""ToF↔相机映射的标定与只读探针。

`map_report` 由若干 (stream_u, stream_v, tof_x, tof_y) 样本最小二乘出仿射四参数
（两轴各一条直线）。`--live` 只读：读 K230 结果流，对每个带 depth_mm 的框算出基座系
三维点打印出来，供操作者跟尺子对。**不连 ROS、不发任何指令。**
"""
import argparse
import math
import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[1]))

from arm_grasp import geom, observe            # noqa: E402


def map_report(samples):
    """samples = [(u, v, tx, ty), ...]，u/v 是推流归一化坐标，tx/ty 是 ToF 归一化坐标。

    返回 {'ax','bx','ay','by','residual_px','n'}。样本少于 3 个、或某一轴在自身输入上
    退化（所有 u 相同 / 所有 v 相同）时抛 ValueError —— **绝不返回一个假解**。
    """
    if len(samples) < 3:
        raise ValueError('至少 3 个样本才能解仿射（实得 %d）' % len(samples))

    def fit(xs, ys):
        n = len(xs)
        mx, my = sum(xs) / n, sum(ys) / n
        sxx = sum((x - mx) ** 2 for x in xs)
        if sxx < 1e-12:
            raise ValueError('输入没有变化，解不出斜率')
        a = sum((x - mx) * (y - my) for x, y in zip(xs, ys)) / sxx
        return a, my - a * mx

    ax, bx = fit([s[0] for s in samples], [s[2] for s in samples])
    ay, by = fit([s[1] for s in samples], [s[3] for s in samples])
    worst = 0.0
    for u, v, tx, ty in samples:
        dx = (ax * u + bx) - tx
        dy = (ay * v + by) - ty
        worst = max(worst, math.sqrt(dx * dx + dy * dy))
    return {'ax': ax, 'bx': bx, 'ay': ay, 'by': by,
            'residual_px': worst * geom.STREAM_W, 'n': len(samples)}


def _live(host=None, once=False):
    """只读：打印每个带 depth_mm 的框 + 算出的基座系点。"""
    from arm_grasp.arm_kin import from_fields
    r = observe.fresh_result()
    if r is None:
        print('（结果流里没有新数据）')
        return
    for o in r.get('objs', []):
        d = o.get('depth_mm')
        if d is None:
            continue
        u, v = observe.box_center_ai(o['box'])
        print('frame=%s cls=%s depth=%dmm 指向深度分支（关节未知，需配合臂回读才算三维点）'
              % (r.get('frame'), o.get('cls'), d))
    print('（--live 只读；三维点由 grasp 链路用关节回读算）')


def main(argv=None):
    ap = argparse.ArgumentParser()
    ap.add_argument('--live', action='store_true')
    ap.add_argument('--once', action='store_true')
    a = ap.parse_args(argv)
    if a.live:
        _live(once=a.once)
        return 0
    ap.print_help()
    return 0


if __name__ == '__main__':
    sys.exit(main())
```

> `_live` 里**故意不算三维点**：算三维点需要「拍那张图那一刻」的关节回读，
> 那是 `grasp.estimate_point` 的活（它有时间对齐）。探针只报深度，别在这里造第二份几何。

```python
def target_from_pixel_depth(joints, u, v, z_axial_m, k=K_AI320x180_CHN2):
    """像素 + **实测的光轴方向深度** → (目标基座系坐标, 沿射线的欧氏距离)，米。

    这是 `target_from_pixel` 的对偶：那边靠"假设目标落在某个水平面"求 t，
    这边直接用 ToF 实测的轴向深度 Z 反解 `t = Z / (d·轴)`。

    ★ 与平面法的一个实际好处：**不再要求视线别太贴平面**（那边 `d_z > -0.3` 就拒），
    所以浅角度看目标也能测 —— 而浅角度正是平面法最容易"自洽但错"的地方。
    """
    C, d = pixel_ray(joints, u, v, k)
    _, axis = fk(joints)                 # geom.py 顶部已有 `from .arm_kin import fk`
    cos_ax = sum(d[i] * axis[i] for i in range(3))
    if cos_ax <= 1e-6:
        raise ValueError('视线与光轴近垂直（cos=%.6f），深度不可用' % cos_ax)
    t = z_axial_m / cos_ax
    if t <= 0.0:
        raise ValueError('实测深度非正（t=%.4f）' % t)
    P = tuple(C[i] + t * d[i] for i in range(3))
    return P, t
```

```python
    """基座系点 P 相对相机光轴的光轴方向深度（= ToF 报的那个量），米。"""
    C = geom.camera_center(joints)
```

```python
def estimate_point(trace, obs, z_plane_m, latency_s):
    """一条观测 → 基座系目标点 O。

    ★ 两条路：
      * `obs.depth_mm` 有值（ToF 实测）⇒ **射线 × 实测光轴深度**。这是首选。
      * 否则 ⇒ 老的 **射线 ∩ 假设平面 z=z_plane_m**（`--h` 兜底路径）。

    返回 (O, C, d, joints, t_frame)。**绝不返回垃圾深度** —— 算不出来一律 Refused。
    """
    t_frame = obs.t_arrive - latency_s
    fbf = trace.at(t_frame, 'auto')
    j = from_fields(fbf)
    C, d = geom.pixel_ray(j, obs.u_ai, obs.v_ai)
    depth_mm = getattr(obs, 'depth_mm', None)
    if depth_mm is not None:
        try:
            P, _t = geom.target_from_pixel_depth(
                j, obs.u_ai, obs.v_ai, float(depth_mm) / 1000.0)
        except ValueError as e:
            raise _refuse('算不出目标点（实测深度）：%s' % e)
        return P, C, d, j, t_frame
    try:
        P, _, _ = geom.target_from_pixel(j, obs.u_ai, obs.v_ai, z_plane_m)
    except ValueError as e:
        raise _refuse('算不出目标点：%s' % e)
    if d[2] > -0.3:
        raise _refuse('射线太平（d_z=%.3f），深度不可用' % d[2])
    return P, C, d, j, t_frame
```

> ⚠️ 注意 `d[2] > -0.3` 那条**只在平面分支保留** —— 深度分支不该受它限制
> （实测深度下浅角度是能算的，这是 ToF 带来的真实好处）。
