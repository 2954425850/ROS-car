## 漏报

- `k230.host_unknown` 目前挂在 `board` 上，`k230_link` 的 incident 里没有带这条诊断；
  查看 `status` 能看到，但 `why k230_link` 看不到根因建议。二期可把下游诊断复制到 incident。
- `config_drift` 的 `journalctl -g` 在长 boot 日志上会超 5s，且「无匹配」返回 1 被误判为不可读。
  本轮已改为有界 `-n 5000` + 本次 boot 内缓存，复测 `ordering_cycles=0`、`errors=[]`。
- 未做物理拔插（ToF/唤醒模块）与运动互锁，不能声称覆盖。
- **2026-11-18 10:00 追加**：用户喊唤醒词后无响应。日志显示唤醒词正常收到，
  但 `ASR: API error — status=44, request timeout after 23 seconds`。
  旧版 `ASRClient` 把 API 错误吞成空字符串，`voice` 心跳仍显示 OK，守护漏报。
  已修：`ASRClient` 记录 `last_error/last_error_wall/last_ok_wall`，心跳带
  `asr_last_error`；新增 `voice.asr_error` 与 `host.gateway_latency` 规则。
  根因是当前 `TP-LINK_EE82_507` 2.4G：网关 RTT 平均 141→372ms、最大 463ms，
  信号 -53dBm 但延迟极差；守护现在会直接报“WiFi 网关延迟高”。
