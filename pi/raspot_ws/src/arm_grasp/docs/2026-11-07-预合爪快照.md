# 2026-11-07 预合爪快照（close shot）：先量清楚偏差是哪一半

## 为什么做这个

末段是**视觉闭眼**：进 `close` 之前冻结目标点 O，之后只用关节回读往下走（`grasp.py`
的 `aim_hold` / descend 冻结）。于是每轮的实际偏差 =

    冻结时 O 不准  +  冻结后臂没走到位

两者混在一起，光看"抓没抓到"分不开。用户报的现象是"**不固定方向**地偏移"，
而这句话本身不足以判断该上末段 IBVS 还是该修回差。所以第一步不是加控制，
是**把这两个误差分开量**。

## 它做什么

- `grasp.run()` 在**进 close 的那一拍**（`advance_or_stop` 里 `cur = seq[k]` 之后）
  组一份快照，交给 `Link.shot()`（可选方法，没有就不调）。
- `grasp_server` 的 `ServerLink.shot()` 落盘到 `shot_dir`（默认
  `~/.local/share/arm_shots/`），并在**后台线程**里抓一张 K230 照片。
  照片是后台抓的：`capture_frame` 要等一整个 GOP（1~3s），**不能**卡在 close 那一拍。
- 跑完在 `finally` 里把结果（`code`/`ok`/`grip_p1`/相序）回填进同一个 json。

快照里存的是**原始输入**：框、AI 像素、实测深度、那一刻的关节（回读/指令/目标）、
拍那张图时的关节、冻结的 O、α、s、下垂补偿…… **采集侧一行几何都不算**，
派生量全部在 `shot.deviation()` 里离线重算 —— 换算法不用再跑一遍真机。

## 怎么用

```bash
# 抓 10~20 次（默认就开着，不用改参数）
# 看汇总
python3 -m arm_grasp.shot ~/.local/share/arm_shots
# 或（带画图）
python3 ~/ROS-car/pi/raspot_ws/src/arm_grasp/tools/grasp_shots.py --overlay --out /tmp/ov
# 关掉
ros2 param set /arm_grasp_server shot_dir ''
```

## 怎么读（毫米，基座系）

| 量 | 含义 | 判读 |
|---|---|---|
| `lat` | 爪尖→物体，**垂直于夹爪轴** | 用户说的"横向偏移"就是这个 |
| `tot` (`d_tip`) | 爪尖→物体的总距离 | 本轮真实落点偏差 |
| `ax`  (`axial`) | 沿夹爪轴分量（+ = 目标比爪尖更深） | "扎没扎到位" |
| `rad` (`radial`) | 径向分量（+ = 目标更远离底座） | `bias_r_mm` 调的是这个 |
| `dO`  | 冻结的 O → 用最后一条观测重算的物体位置 | **冻结的代价** |
| `px`  | 物体现在该落的 AI 像素 − 对准该落的像素 | 图上红点到绿叉 |

**判据**

- `dO` 大、`tot` 也大 ⇒ **冻结太早 / 观测太脏** ⇒ 该做"停稳之后再取几帧重算 O"，
  不需要新的视觉算法（最便宜的一步）。
- `dO` 小、`tot` 大 ⇒ **冻结之后臂没走到位**（回差 / 下垂 / 底座松量）⇒ 这时才轮到
  末段有界 XY 修正，而且必须 α 锁死、从固定一侧逼近、修正量设上限。

## 它证明不了什么

`tot`/`lat` 用的还是**同一套几何模型**（FK + 手眼 + 内参）。模型本身偏了，这个数会一起偏。
所以照片必须一起看：`--overlay` 画的红点是"模型认为物体该在这儿"，人眼能直接判
"爪尖实际上是不是套住了它"。**模型和眼睛打架的时候，先信眼睛。**

## 覆盖情况

- `descend → close` 正常收尾、以及"下扎到机械极限就地合爪"（`descend_fallback`）都会拍。
- `dry_run`、以及 preflight 就失败（锁框/无深度）的轮次**没有快照**（那时根本没有 close）。
- 取消/异常打断：快照已经落了盘，`finally` 里照样回填（`result.code='CANCELED'` 等）。
